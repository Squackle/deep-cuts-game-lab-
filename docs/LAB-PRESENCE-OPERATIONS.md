# Shared Lab presence operations
Issue #343. Root `/` and legacy `/lab/` are Game Lab, not Hive Run. Unknown routes default to Game Lab. Existing clients continue anonymous 30-second pulses, including background tabs, with 180-second KV expiry. A successful local/browser-shared lease and count is reusable for 30 seconds; foreground page changes update attribution promptly, and failed requests never refresh cache timestamps. Per-tab single flight coalesces simultaneous focus/visibility/pageshow/online events. Cross-tab storage is best-effort (not atomic or guaranteed; restricted storage and races can result in duplicate requests). A stale or failed count displays unavailable, not a fabricated zero.

At 30 seconds, one continuously open tab historically sends 120 POST + 120 GET per hour plus event-driven bursts. Three tabs can send 360 of each per hour. With staggered successful pulses sharing storage, the new steady-state target is approximately 120 of each per browser-hour, plus page changes and races. GET lists up to ten KV pages; one GET can cost more than one KV list operation. These are theoretical request counts, not measured billing or live traffic. Actual savings depend on tab count, errors, synchronization and visitor behavior. Do not increase TTL, suppress background heartbeats, create production load, or modify bindings to measure this.

The API accepts both newer labels GRAFTBOUND and ARCHEMANCY; both game owners can elect to load shared presence.js/presence.css in their own entry pages after review. This PR deliberately does not edit their active game-owned entry HTML or silently enable new telemetry. No new user identifiers, accounts, scores or personal records. POST rejects oversized bodies even without an honest Content-Length. Anonymous origin checks are browser cross-origin defense, not authentication or a complete abuse prevention system.
