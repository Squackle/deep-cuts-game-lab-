## Proposed final interaction design for owner signoff (#205)
Card-first compact dialog; no ornate/radial decoration. Desktop: title + reason, genuine card face/detail on left, two equal explicit actions on right, short consequence under each. Mobile: vertical card/detail then two 44px+ full-width actions; no horizontal scroll, board remains visible outside the panel. Opt shows actual top card, source spell and Library count. Keep on Top => draw that card; Put on Bottom => move it then draw next available real card. One-card library makes both paths draw that same card; empty library follows approved RPG refill/empty policy and never invents cards. Mandatory choice locks Escape/backdrop; focus lands on heading or neutral control (not auto-commit), Tab containment, screen-reader status on resolution, no keyboard default destructive action. After accepted choice restore prior focus, update history and draw animation. UI state derived from saved pending choice, not hidden client-only selection; replay records one stable choice argument, not animations or card artwork. Duplicate clicks, refresh, invalid payload, server segment retry and choice ordering are acceptance cases.
Equipment picker: source card, legal bearer, cost, current→new P/T, immediate-death warning with explicit confirm for hero; voluntary cancellation is free. Abilities entry retains upper-right location, count/readiness, Graft Powers and Equipment Abilities, original subtle sigil with reduced-motion static fallback. Mandatory trigger queue only interrupts real choices; passive triggers appear in chronological history. No remembered decisions without separate ranked review. This is a proposed wireframe specification, not approved artwork or runtime implementation.
